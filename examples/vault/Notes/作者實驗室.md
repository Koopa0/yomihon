## 只在副本動手

從 repository 根目錄開一個終端，把範例複製到新目錄。下面的檢查需要自行安裝或編譯的 yomihon；課文與程式版本應相符。

```sh
lab=$(mktemp -d)
cp -R examples/vault/. "$lab/"
yomihon check --root "$lab" --format json --all
```

指令結束後，你會看到三項刻意安排的診斷。**沒有加 `--deny` 時，列出問題仍可退出 0**；這不等於沒有問題。

| 規則 | 在哪裡看 | 這個例子要你辨認什麼 |
| --- | --- | --- |
| schema.enum | [[A note with a fault in its frontmatter]] | status 不在契約列出的值中 |
| link.broken | [[Wikilinks in this dialect#The three answers]] | 沒有檔案回答這個名稱 |
| link.section_missing | [[Wikilinks in this dialect#Fragments]] | 檔案存在，但所指的章節不存在 |

```sh
yomihon check --root "$lab" --deny warn --all
```

這次預期退出 1，因為 warn 門檻也包含 error。退出 2 則是命令無法完成，例如契約無法使用；不能當成「檢查完、有兩個問題」。

這三項是 CLI 的預期清單。整體狀況頁還會呈現正文 wikilink 的引用情況等資訊，不能把兩邊的數字當成同一種總數。

## 把一個問題改好，再查一次

在副本中，把故障筆記的 nearly-ready 改成契約允許的值，再執行相同的檢查。預期只少掉 schema.enum；另外兩條連結仍有它們自己的問題。

> [!question]- 如果三項一起消失，算成功嗎？
> 先確認檢查的 root、範圍與退出碼。把筆記搬到不受檢查的地方、刪掉問題所在的檔案，或讓命令根本無法執行，都可能讓你看不到原來的輸出。你需要的是修正後仍被同一個檢查讀到的案例。

[[Diagnostics are reports]] 說明這個分工：程式回報，作者修改。[[Building yomihon from source]] 與 [[L01 Point yomihon at a folder]] 則保留了一組舊／新教材的替代關係；archived 表示內容歷史，不是學習完成。

## 看看外部修改如何出現

1. 用 `yomihon "$lab"` 服務副本，打開 [[R01 先把問題寫小]]，留下待續位置。
2. 在編輯器替副本的這篇課文加一小段普通文字，存檔。
3. 留在原本的瀏覽器頁面，等它檢查到檔案變動，閱讀更新提示，再重新載入。
4. 回首頁，觀察待續入口的內容變更提示。它仍帶你回原筆記；正文已改動，原位置可能偏移，需要重讀附近內容。

這個過程只示範外部修改如何被看見。不要把「畫面還沒更新」解讀成「檔案沒改」，也不要在真實筆記上故意製造競爭寫入。

## 其他兩個問題，用其他命令問

先按 Ctrl-C 停止服務，再在同一個終端執行，讓 lab 仍指向剛才的副本。

```sh
yomihon coverage --root "$lab" --format json
yomihon exists --root "$lab" --format json 反例
```

coverage 回答概念筆記如何被連到與掛上地圖，不是學習完成率。exists 查名稱是否有對應檔案，不保證其中的說法正確。Diary 在這份契約的隱私清單中，命令列的回答不會直接輸出它的內容；本機閱讀頁仍能打開它。
