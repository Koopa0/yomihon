現在手邊有問題、來源、第一版解釋與修正。把它們放在同一個資料夾，別人就知道該怎麼讀了嗎？

資料夾回答「放在哪裡」。這本書還需要回答另外兩件事：哪些內容有先後依賴，哪些只在卡住時才需要。

## 替下一位讀者排一次

一位不會 Go 的讀者，想完成第三課的反例練習。下面三份材料，你會讓哪些成為必讀？哪些適合隨手查閱？

- 名稱解析的三種結果
- 讀一段 Go 的分支
- 反例這個詞的解釋

先排出自己的路線，再想一個會需要不同安排的讀者。

> [!question]- 順序取決於這次要做的事
> 核對結論需要來源，所以練習一定得能走到「名稱解析的三種結果」。Go 支線提供更深入的驗證，但不必成為完成反例練習的門檻。「反例」則是忘了可以再查的概念。
>
> 這三種關係可以分別用課文連結、local 支線、概念筆記表達。不需要把所有可讀的東西都塞成上一課與下一課。
>
> 反例是程式碼審查者：如果任務變成檢查實作是否符合描述，Go 就不再是可略過的背景。課徑替一個任務排順序，不替所有讀者宣布唯一順序。

## 明確寫出主線和支線

這本書使用下面的形狀。花括號是作者給 yomihon 的宣告，正常閱讀時不會顯示。

```markdown
## 提出可以核對的問題 {sequence=primary}

- [[R01 先把問題寫小]]
- [[R02 追到宣告的地方]]
    - 想讀實作時 {sequence=local}
        - [[R06 讀一段 Go 的分支]]

## 用證據改寫理解 {sequence=primary}

- [[R03 用反例檢查理解]]
```

主線的下一課從 R02 到 R03。選讀支線有自己的順序，不會把 R06 算進主線的五課。`none` 則保留一組可讀的參考連結，不產生上一課與下一課。

## 動手：在自己的副本加一條路徑

以下從 repository 根目錄執行，只操作新建的暫存副本。不要直接修改公開 demo。

```sh
lab=$(mktemp -d)
cp -R examples/vault/. "$lab/"
```

用自己的編輯器在副本的 Notes 目錄新增一篇筆記，寫入：

```markdown
---
title: 我的查證路線
type: study-path
status: draft
lang: zh-Hant
---

## 核對一次 {sequence=primary}

- [[R01 先把問題寫小]]
- [[R03 用反例檢查理解]]

## 需要時查 {sequence=none}

- [[反例]]
```

副本已帶著契約，所以 `study-path` 和 `draft` 都有定義。檔名由你決定；存好後，開啟副本並檢查課程是否真的出現、是否只有兩課：

```sh
yomihon "$lab"
```

這個命令會持續執行；在瀏覽器開啟它印出的本機位址，結束時按 Ctrl-C，再在同一個終端依 [[作者實驗室]] 執行檢查。==課文能讀，不等於課徑投影正確==：最後必須看一次實際課程。

[[閱讀的工具箱]] 則把這些概念按用途分組。它是一張地圖，適合回查，不要求你從第一列一路讀到最後。
